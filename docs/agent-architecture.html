How ClaimCompanion's agents are orchestrated

Every customer turn runs as one LangGraph StateGraph: guardrails, a supervisor that routes, one of five specialist agents, an empathy responder, and an output check. Five back-office agents run in graphs of their own and coordinate through the claims database rather than by calling each other. The model writes and classifies; it never decides a claim outcome.

How agents share work

Agents never call each other directly. They write to the claims database, and other agents read it on their next turn or sweep. That keeps each agent's permissions narrow and every hand-off in the audit log.

Document verifier

documents/pipeline.py · started on upload by a background thread, process(doc_id). Any stage can reach a verdict early; finish is the only place one is written.

Registration bot

fnol/run_graph.py · one graph shared by the scripted bot (registration.py) and the agentic bot (agentic_registration.py), which differ only in their Flavor.

Reviewer relay

agents/relay_graph.py · used by handoff.deliver_reviewer_response (kind relay) and handoff.request_information (kind request).

AIOps agent

aiops/graph.py · runs every AIOPS_INTERVAL_SECONDS (300) or on demand from Oversight → AIOps. Checkpointed under aiops:<run_id> so an approval pause survives a restart.

Runtime

PieceWhereWhat it does
Checkpointeragents/runtime.pyOne SQLite file for all graph checkpoints. Threads: conv:<conversation_id> for chat, aiops:<run_id> for sweeps. Replay with GET /admin/graph/conversations/{id}/history.
Telemetryops/telemetry.pyinstrument(graph, node, fn) wraps every node: an OpenTelemetry span <graph>.<node>, the cc_graph_node_seconds histogram, and an error counter. Prometheus at /metrics.
LLM gatewayllm/gateway.pyThe only caller of a model. Versioned YAML prompts, PII redaction, tier ladder, response cache, token and cost metering, template fallback.
Model tiersllm/providers.pyMini openai/gpt-oss-20b for routing; primary openai/gpt-oss-120b for writing and extraction; served by Groq.
Streamingapi/v1/chat.pygraph.stream(stream_mode=["custom", "values"]): custom frames go to the WebSocket, the last values become the turn's result.

What isn't a graph: the reviewer copilot, the chase drafter and the consistency explainer in staff.py are single LLM calls behind an endpoint. They have no branching, so a graph would add nothing.
